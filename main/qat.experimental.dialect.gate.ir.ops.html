qat.experimental.dialect.gate.ir.ops module

Operations of the gate dialect.

Each gate is its own op, such as HOp or CZOp. Base classes hold the shape of each family of gates: the qubits a gate acts on, the angles it takes, and the rule that each result keeps the qubit type of its operand. Angles are f64 operands, so a gate can take a run-time parameter as well as a constant.

Every op that takes a qubit consumes it, so a qubit value should be used once. Op verifiers check this only within one op: a two-qubit gate or a barrier rejects the same qubit twice. Checking it across a whole program is left to a verification pass.

Gate ops are not Pure. They change the state of a qubit, and dead-code elimination would otherwise delete a gate whose result is unused.

class BarrierOp(qubits)

Bases: BarrierOp, IRDLOperation, Operation, _IRNode, ABC, object

Optimisation barrier across a set of qubits.

Stops optimisations moving operations on these qubits across the barrier. It carries no timing: whether it also lines up the qubits’ timelines is decided when it is lowered. Takes a variadic set of distinct qubits and returns each one unchanged.

Variables:

  • result_qubits – The qubits after the barrier.
