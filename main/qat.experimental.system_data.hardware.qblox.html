qat.experimental.system_data.hardware.qblox module

Qblox-specific derived view of canonical system data.

This module describes the configuration of Qblox hardware with a single data structure that mirrors the physical RF chain of a Qblox Cluster. Qblox modules are control hardware devices which can control many qubits and perform readout depending on the module type. Each tone generated by the module is called a generator (aka physical port). A generator is a subsection of the module (often a sequencer + local oscillator). The generator is responsible for control of a single mode of a qubit and can be mapped to a frame. This configuration dictates the boundaries of the generated tone and is used for legalisation and for lowering the pulse dialect to the Q1asm dialect (Qblox IR).

As an example, a single output tone is produced by combining a local oscillator with a sequencer’s NCO (e.g. an LO at 4.4 GHz mixed with an NCO at 240 MHz yields a 4.64 GHz output). Each such tone-generation unit is captured as a Generator bound to a physical port. The QbloxHardwareView ties the generators together into a derived view of CanonicalSystemData.

The model follows the hardware building blocks documented by Qblox (see, for example, the QRM-RF architecture): a Cluster is populated with modules (QCM, QCM-RF, QRM, QRM-RF, QRC); each module exposes one or more RF ports; and each port is fed by a set of sequencers and, on RF modules, one or more local oscillators.

classmethod derive(parent, **kwargs)

Build a Qblox hardware view from canonical system data.

The canonical data is produced by materialising a Qblox (purr) calibration. Every value is derived from that data rather than hardcoded:

  • The module type is resolved from the external resource object_type or parsed from the port/oscillator identifiers (e.g. QCM-RF); a ValueError is raised if it cannot be determined.

  • The Cluster slot is read from the port’s baseband attributes; a ValueError is raised if it cannot be determined.

  • Ports are grouped into physical modules by (instrument_id, slot).

  • Each canonical channel becomes a QbloxGenerator: a sequencer (readout if the port supports acquisition, otherwise control) paired with the channel’s local oscillator. Sequencers are routed to outputs using the module default, i.e. each output receives a contiguous block of the module’s sequencers (on a QCM-RF, sequencers 1-3 drive the first output / LO and 4-6 the second).
